# `pgrx 0.20.1`, correctness fixes and optimization benchmark

Local Linux ARM64 comparison on PostgreSQL 19.0 GA / PostGIS 3.7.0 between
`origin/master` (`67ca2f2`, `pgrx 0.20.0`) and the updated `0.0.9` build
(`pgrx 0.20.1` with read-only catalog lookup, per-call-site `FmgrInfo` caching,
in-place Cartesian `POINT` transformation, direct `RTPOINTARRAY` traversal, and
Jenks optimizations). Both builds use Rust 1.99.1, generic CPU targets,
`opt-level=3`, fat LTO, and C `-O3`.

## Method

- **Paired comparison**: Both shared libraries ran against the same PostgreSQL
  19.0 instance and identical tables in separate schemas (`base` and `opt`).
  Each observation ran in a fresh backend loading only one library (preventing
  `RTLD_GLOBAL` symbol sharing), executing one excluded warm-up and one measured
  `EXPLAIN (ANALYZE, TIMING OFF)` query across 10 alternating pairs (`base`/`opt`
  then `opt`/`base`). JIT and query parallelism were disabled; `work_mem` was
  `8MB`.
- **Standard README suite**: One excluded warm-up and five measured runs of
  `scripts/benchmark_pg18.sh` (`ROWS=200000`, `PG_MAJOR=19`) and
  `scripts/benchmark_jenksbins.sh` (`ROWS=100000`, `DISTINCT_VALUES=1000`,
  `BREAKS=7`, `WORK_MEM=8MB`) on the updated `pgrx 0.20.1` extension, with JIT
  and parallelism disabled.
- **Datasets**:
  - Points: 200,000 WGS84 points, uniform within the China bounding box, seed `0.42`.
  - Toasted lines: 256 externally stored `LINESTRING` geometries, 1,000 vertices each.
  - Polygons: 5,000 `POLYGON` geometries with one exterior ring and one hole (20 vertices each).
  - Standard text target: first 1,000 points transformed to `+proj=longlat +datum=WGS84 +no_defs`.
  - Duplicate-heavy Jenks: 100,000 float8 rows, 1,000 distinct values, 7 classes.
  - Unique Jenks: 10,000 distinct float8 values, 7 classes.

## Paired results (`pgrx 0.20.0` vs `pgrx 0.20.1`)

Times are milliseconds (median and min-max range across 10 pairs). Negative change
means faster. Coordinate queries consume `ST_X` once per transformed geometry.

| Workload | `pgrx 0.20.0` baseline | `pgrx 0.20.1` optimized | Change | Speedup |
| --- | ---: | ---: | ---: | ---: |
| Direct points `4326 -> GCJ02` (200k) | 50.412 (49.746-51.082) | 37.816 (37.668-39.470) | -25.0% | 1.33x |
| Text alias `4326 -> 'GCJ02'` (200k) | 56.585 (56.162-59.829) | 42.020 (41.547-42.692) | -25.7% | 1.35x |
| Composed `4326 -> BD09 -> 3857` (200k) | 157.541 (155.163-162.208) | 122.186 (121.388-123.774) | -22.4% | 1.29x |
| Standard delegation `4326 -> 3857` (200k) | 54.154 (49.052-62.900) | 43.790 (40.666-51.522) | -19.1% | 1.24x |
| Toasted lines `4326 -> GCJ02` (256x1000) | 16.233 (15.153-20.540) | 14.745 (14.281-15.923) | -9.2% | 1.10x |
| Polygons `4326 -> GCJ02` (5k x 20v) | 11.402 (10.467-13.058) | 9.946 (8.798-11.241) | -12.8% | 1.15x |
| Standard text target 2-arg (1k) | 41.561 (40.904-51.273) | 41.862 (39.048-46.664) | +0.7% | 0.99x |
| Jenks array (100k / 1k distinct / 7) | 4.293 (4.122-5.444) | 3.656 (3.582-3.984) | -14.8% | 1.17x |
| Jenks aggregate (100k / 1k distinct / 7) | 5.909 (5.850-8.147) | 5.426 (5.357-5.855) | -8.2% | 1.09x |
| Jenks array unique (10k / 7) | 4.188 (3.915-4.278) | 1.715 (1.628-1.870) | -59.1% | 2.44x |

Notes:

- **Output parity**: All sampled geometry outputs (`ST_AsEWKB`) and all three
  Jenks outputs matched byte-for-byte with zero mismatches.
- **Parallel query safety**: Under `SET debug_parallel_query = on`, the baseline
  failed with `ERROR: cannot assign transaction IDs during a parallel operation`
  (due to read-write `Spi::get_one` during PostGIS catalog resolution), whereas
  the updated build succeeded.
- **Text target 2-arg**: Both builds spend virtually all time inside PostGIS's
  SQL `st_transform(geometry, text)` (`spatial_ref_sys` lookup and per-row PROJ
  string setup), matching direct PostGIS `ST_Transform` within measurement noise.

## Standard README suite (PG19.0 GA, `pgrx 0.20.1`)

Median and min-max range across five measured runs after one warm-up. Coordinate
queries match `scripts/benchmark_pg18.sh` (`ST_X(g) + ST_Y(g)`), so absolute times
are not directly comparable with the single-`ST_X` paired table above.

### Coordinates (200,000 points)

| Workload | Median (ms) | Range (ms) |
| --- | ---: | ---: |
| Native `4326 -> GCJ02` | 77.550 | 75.453-79.085 |
| Regex SQL `4326 -> GCJ02` | 5502.505 | 5453.839-5550.725 |
| Native `4326 -> BD09 -> 3857` | 244.361 | 241.932-244.529 |
| Regex SQL `4326 -> BD09 -> 3857` | 15142.707 | 15107.521-15245.809 |

### Jenks (100,000 rows, 1,000 distinct values, 7 classes, `work_mem=8MB`)

| Workload | Median (ms) | Range (ms) |
| --- | ---: | ---: |
| CartoDB SQL `CDB_JenksBins` | 88.865 | 84.256-95.117 |
| Rust array `ST_JenksBins` | 9.520 | 8.976-10.405 |
| Rust aggregate `ST_JenksBins` | 8.027 | 7.859-8.798 |

These are local ARM64 results, not a performance guarantee on amd64 or other
workloads. Raw plans, intermediate outputs, and driver scripts remain outside
the repository.
